# 激活、行程与三态

通用机制位于lib/core/activation；聊天适配及默认策略位于lib/application/agents/activation；行程匹配位于lib/domain/services/schedule_policy.dart。机制不依赖页面、SDK或OPFS。

## 当前规则

- 每角色默认5–30秒均匀随机检查，可配置区间；收到消息不直接激活。
- 行程规则支持每天、每周、每年月日、具体日期及日期范围，时间段左闭右开，可跨午夜，采用角色独立IANA时区。
- 多条规则命中时选择最新修改顺序的规则；仅改活动文案不恢复衰减。
- 未命中行程使用角色运行设置的默认激活概率，默认50%，允许0–100%及小数。
- 常规抽中后延迟0–5秒；非零概率的实际行程切换保证安排一次查看，延迟U[5(1-p),5+55(1-p)]秒，p按0–1计算。
- 未查看消息中被@时概率乘2，多次不累计；基础0始终为0。
- 连续AI消息n的系数d=max(0.05,2^(-max(0,n-6)/4))，有效概率min(1,p×@倍率)×d。5%是系数下限，不是所有角色的最终概率下限。
- 用户发言使该会话的连续AI尾部归零；实际行程切换恢复该角色的会话基线。基础100%仍可因衰减低于100%，模型也可自主沉默。

## 三态

| 状态 | 处理 |
| --- | --- |
| 暂停 | 等到下次检查，根据当前快照评估 |
| 激活 | 任务已排队，等待延迟、角色串行顺序或模型额度 |
| 处理中 | 已进入上下文/工具循环；完成或失败后释放，再处理队列 |

每角色每目标最多一个等待项，重复来源合并，不推迟已有到期时间。当前目标处理中时行程切换不额外排第二次任务；其他目标可排队。同角色串行，不同角色并行，API/模型额度单独控制。

等待进入概率0时取消等待；处理中的行程/概率变化不取消已进行的处理。新消息使当前上下文代次失效，不并行开启同角色第二个HTTP；旧HTTP自然结束，丢弃未提交旧结果后基于最新历史继续，保留已执行过程与累计预算。

## 启动与扩展

数据初始化成功后自动启动。浏览器后台是否新检查由偏好控制；冻结/关闭无法保证执行，恢复按当前时间评估，不重放积压的每一次检查。

扩展激活规则实现ActivationPolicy，再在AgentRuntime装配时注入；新来源统一生成ActivationRequest。不要让SDK、Widget或文件系统进入core，也不要把模型执行逻辑塞回调度器。依赖及边界测试见17-modular-architecture.md。
